# Google sign-in and separate trading workspaces

The public dashboard uses Firebase Authentication's Google popup. The Firebase web configuration identifies the project and is public by design; it is not a broker credential. Analytics, Firestore and Storage are not enabled by the login integration. Google login does not need or ship a service-account private key. The independent optional [encrypted Firestore backup worker](FIRESTORE_BACKUP.md) requires separate private server credentials and does not change the execution store or broker authentication lifetime.

Enable Google in Firebase Console → Authentication → Sign-in method and authorize the actual dashboard domain in Authentication → Settings → Authorized domains. The production client uses project `mavrix-trading` and auth domain `mavrix-trading.firebaseapp.com`. Preview domains must be authorized separately before testing Google there. The code uses the Firebase modular app/auth packages only.

Set `N009_FIREBASE_PROJECT_ID=mavrix-trading` and `N009_MULTIUSER=true` on Vercel. Deploy the updated external engine and set `N009_MULTIUSER=true` there **before** exposing Google access. Both sides must use the same private gateway secret. The legacy cloud Paper transport does not support these workspaces.

The server verifies Firebase ID tokens with RS256 signatures and Google's fixed public certificate endpoint, including issuer, project audience, expiry, issued-at, subject, verified email, Google provider and recent authentication for initial sign-in. See [Firebase's verification requirements](https://firebase.google.com/docs/auth/admin/verify-id-tokens). Access cookies remain Secure, HttpOnly, SameSite=Strict and valid at most one hour, never beyond the verified ID-token expiry.

Firebase manages persistent browser sign-in using browserLocalPersistence. A separate signed HttpOnly refresh grant remembers the same workspace for a maximum of 30 days after fresh Google authentication. It cannot access the engine by itself. Silent renewal requires this grant plus a newly issued, cryptographically verified Firebase ID token for exactly the same UID/project. Renewal never extends the original 30-day deadline. The dashboard refreshes before expiry and after browser wake without remounting the workspace on a successful same-user renewal. Temporary certificate-service failures return a retryable response, retain saved identity, and do not ask for a fresh login. Failed startup checks retry automatically; successful same-user checks preserve the mounted dashboard. Profile shows the remembered-login deadline separately from the hourly access-token renewal and broker expiry. Existing seven-day grants retain their original expiry; a fresh interactive sign-in receives the 30-day grant. Logout clears both server cookies and Firebase state; account login/logout changes notify other tabs to clear cached workspace views. Broker passwords, OTP/TOTP codes and broker keys/tokens are not stored in this browser identity state.

Sessions are stateless: disabling/revoking a Firebase user does not immediately invalidate an already issued dashboard access cookie. Fresh token issuance is required for renewal; an existing access cookie expires within one hour. Rotate the gateway secret to revoke all signed access and refresh cookies immediately.

The gateway derives a workspace ID from the verified project and Firebase UID. Email addresses and browser-supplied UID/tenant headers do not select a workspace. It signs a separate short-lived engine assertion. AWS requires both the gateway secret and this assertion. Assertion and browser-cookie signatures have different purposes and cannot substitute for each other.

Each Google user gets a separate controller, market feed, CSRF token, SQLite database, random encryption key, settings, broker connection, sessions, backtests and history under `/var/lib/nifty009/tenants/<opaque-id>`. Nothing is copied from the owner account into a new Google workspace. **Owner access** retains the existing private password and original root workspace; do not share that password with other users. Google identities are not automatically linked to it.

A persistent broker-account ownership index prevents ordinary restore or arbitrary browser requests from attaching another workspace's broker. A fresh successful mStock verification may move that account's connection only if the old workspace is stopped, flat, has no pending intent and no in-flight controller operation. The old feed and encrypted broker credentials are removed; its private history/settings are not copied. The new workspace stores its own verified token. If the old workspace is active the move fails closed. A verified token is retained only in the bounded private login flow when a move is blocked, so a safe retry does not submit the OTP twice. Disconnect and token expiry alone do not release ownership.

Every user must connect their own mStock account, register the actual AWS outbound IP in their own API key, and run their own diagnostics. Signing in never starts a strategy or places an order. Saved workspaces restore on engine startup and retain their individual existing session rules. Closing a browser does not stop a started session.

The current small host has bounded admission: `N009_MAX_WORKSPACES=4` Google workspaces plus the owner, to avoid unlimited process growth. Capacity errors fail closed; they never fall back to the owner workspace. This is not a claim of unlimited concurrency or load-test certification. Database and controller isolation is application-level within one dedicated service, not a separate VM per user. Host administrators can access server state. Back up every workspace's database **with its encryption key** and preserve the owner ownership index.

Upgrade only when sessions are stopped and flat. Engine shutdown checkpoints each workspace without placing square-off orders. Interrupted running sessions retain their original day rules, reference, trade/order history and entry gates; valid broker authentication and position verification are required to resume. Explicit Stop & square off remains a separate action. Same-day setting edits do not create a fresh execution session; they apply next trading day. The pre-migration owner backup is retained privately on the engine host. Caddy's default runtime logger removes request headers, including gateway authentication and workspace assertions. Do not enable body logging or copy environment files into source or static assets.

Dashboard persistence does not renew mStock authentication. mStock access tokens expire within 12 hours or at midnight IST, whichever comes first; a fresh SMS OTP or enabled TOTP is then required. The execution service runs independently of browser sign-in and restarts on failure, but orders require valid broker credentials and fresh data. Starting a new trading day remains explicit; no daily automatic trading activation is added.
